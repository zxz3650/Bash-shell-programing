# 04-1. 경로와 권한의 실행 모델

상대 경로의 기준은 스크립트 파일 위치가 아니라 프로세스의 현재 작업 디렉터리다. 스크립트가 터미널에서는 동작하지만 예약 실행에서 실패하면 경로와 권한부터 확인한다.

{% hint style="info" %}
### 🧭 학습 목표

- 절대·상대 경로와 스크립트 위치를 구분한다.
- 파일과 디렉터리의 r·w·x 의미를 설명한다.
- umask가 새 파일에 미치는 영향을 관찰한다.
- 심볼릭 링크와 경로 검사 한계를 구분한다.
{% endhint %}

## 학습 전 확인

읽을 수 있는 파일인데 접근이 거부되는 이유는 무엇인가? 실행 파일이 다른 디렉터리에 있으면 상대 경로는 어디를 가리키는가?

## 1. 경로 기준 관찰

```bash
lab_dir=$(mktemp -d)
mkdir "$lab_dir/input" "$lab_dir/output"
printf 'sample\n' > "$lab_dir/input/item.txt"
(
    cd "$lab_dir" || exit 1
    printf 'cwd=%s\n' "$PWD"
    cat input/item.txt
)
printf 'parent cwd=%s\n' "$PWD"
```

괄호 안의 cd는 서브셸에만 적용되어 부모 위치를 유지한다. 예제 출력 경로는 환경마다 다르지만 sample 내용은 같아야 한다. 실행 파일 위치를 구할 때는 다음 패턴을 쓴다.

```bash
# 저장된 Bash 스크립트 안에서 사용
script_dir=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)
```

이는 스크립트 자체가 심볼릭 링크인 경우 실제 대상까지 항상 추적하는 만능 정규화가 아니다. 배포 경로 정책을 별도로 정한다.

## 2. 파일과 디렉터리 권한

| 비트 | 파일 | 디렉터리 |
|---|---|---|
| r | 내용 읽기 | 이름 목록 읽기 |
| w | 내용 변경 | 항목 생성·삭제, 보통 x도 필요 |
| x | 실행 | 경로 탐색·하위 항목 접근 |

파일 삭제 가능 여부는 파일 자신의 w만으로 결정되지 않는다. 부모 디렉터리 권한과 sticky bit, ACL 등도 영향을 준다. `chmod 777`로 모든 실패를 해결하지 않는다.

## 3. umask

```bash
(
    umask 077
    printf 'private\n' > "$lab_dir/output/report.txt"
    mkdir "$lab_dir/output/private"
    ls -ld "$lab_dir/output/private" "$lab_dir/output/report.txt"
)
```

일반적인 새 파일은 600, 새 디렉터리는 700 권한이 된다. umask는 생성 요청 권한에서 비트를 제거한다. 기존 파일의 권한은 바꾸지 않는다. 기본 ACL 등이 있으면 결과가 달라질 수 있으므로 실제 권한을 확인한다.

## 4. 검사와 실제 읽기는 다른 시점

`[[ -f $path && -r $path ]]` 뒤에도 파일이 사라지거나 권한이 바뀔 수 있다. 실제 cat·cp·mv 결과를 확인해야 한다. 문자열 접두사가 작업 폴더와 같다는 이유만으로 경로가 내부에 있다고 판정하지 않는다. `..`와 심볼릭 링크가 경계를 바꿀 수 있다.

본 실습은 자신이 만든 임시 폴더를 사용한다. 적대적인 동시 변경까지 막는 파일 디스크립터 기반 처리는 Bash만으로 일반화하기 어려우므로 별도 구현을 검토한다.

## 🧪 직접 해보기

1. 같은 파일을 절대·상대 경로로 읽는다.
2. 서브셸 안과 밖의 PWD를 비교한다.
3. umask 022와 077에서 각각 새 파일을 만들어 권한을 비교한다.

### 해설

읽기 실패는 파일 없음·현재 위치 오류·권한 부족 등으로 나뉜다. 경로 문자열만 보지 않고 PWD, id, 부모 디렉터리 권한을 함께 기록한다.
