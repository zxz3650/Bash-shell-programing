# 11-1. 제한된 동시성과 작업 결과 회수

파일마다 &를 붙이면 파일 개수만큼 프로세스가 만들어질 수 있다. 먼저 직렬 결과를 검증하고, 동시에 실행할 작업 수를 제한한 뒤 결과가 같음을 확인한다.

{% hint style="info" %}
### 🧭 학습 목표

- 작업 수와 동시 실행 수를 구분한다.
- 배치별 PID를 저장하고 모두 wait한다.
- 입력 순서와 완료 순서를 분리한다.
- 일부 작업 실패를 전체 상태로 전달한다.
{% endhint %}

## 0. 학습 전 확인

10개 입력을 동시성 2로 처리하면 전체 작업이 2개인가? 출력 파일 하나에 여러 작업이 동시에 쓰면 어떤 문제가 생기는가?

## 1. 배치 실행 모델

```text
입력 1~2 시작 → 둘 다 wait → 입력 3~4 시작 → 둘 다 wait → 결과 병합
```

이는 단순한 배치 모델이다. 먼저 끝난 슬롯을 즉시 재사용하는 워커 풀보다 효율이 낮을 수 있지만 Bash 3.2에서도 흐름을 명확하게 구현할 수 있다. `wait -n`은 더 새 Bash 기능이므로 기본 교재가 의존하지 않는다.

## 2. 제공 예제 실행

저장소 루트에서 실행한다.

```bash
bash examples/parallel/run-workers.sh 2 \
    examples/log-report/fixtures/events.log \
    examples/log-report/fixtures/events.log
```

```text
1    5
2    5
```

실제 구분자는 탭이다. 첫 열은 입력 번호, 둘째는 wc -l의 개행 수다. 마지막 개행이 없는 파일에서 “레코드 수”와 다를 수 있음을 명시한다.

## 3. 구현 읽기

예제는 각 작업이 고유 번호의 임시 파일에 쓰도록 한다. 부모는 PID를 배열에 저장하고 배치가 차면 wait한다. 작업 중 하나라도 실패하면 최종 병합 결과를 출력하지 않고 상태 1을 반환한다.

| 단계 | 책임 |
|---|---|
| 입력 검증 | 작업 수 1~8, 파일 인수 존재 |
| 작업 실행 | 파일별 개행 수를 별도 파일에 기록 |
| 상태 회수 | 직접 자식 각각 wait |
| 병합 | 모든 성공 후 입력 번호 순 출력 |
| 정리 | 자식 종료·회수, 자기 임시 폴더 제거 |

## 4. xargs 대안

```bash
# GNU/Linux 예제: GNU xargs의 -r 사용
find ./samples -type f -print0 | xargs -0 -r -n 1 -P 2 wc -l --
```

-0은 파일명 경계, -n은 호출당 인수 수, -P는 동시성이다. 출력 순서는 입력 순서로 보장되지 않는다. GNU의 -r 등 옵션은 플랫폼 차이를 확인한다. 이 예제는 총합을 별도로 보장하지 않는다.

## 🧪 직접 해보기

1. 동시성 1·2·4의 출력이 같은지 diff로 비교한다.
2. 입력 중 하나를 없는 파일로 바꾼다.
3. 동시성 0·9·abc가 사용 오류로 거부되는지 확인한다.

### 해설

병렬화의 성공 기준은 빨라졌다는 것만이 아니다. 동일 결과·제한된 부하·실패 전파·자원 정리가 함께 충족되어야 한다.

## ✅ 완료 기준

- [ ] 각 직접 자식의 상태를 회수한다.
- [ ] 실패 시 부분 결과 정책이 명확하다.
