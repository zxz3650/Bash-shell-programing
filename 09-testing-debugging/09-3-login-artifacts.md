# 09-3. 로그인 아티팩트를 교차 검증하고 분석 오류 테스트하기

합성 자료 실습은 [공통 준비](../examples/security-labs/README.md) 뒤 ch09.sh를 실행합니다. malformed.psv는 실습이 결과 폴더에 만드는 잘못된 입력 예입니다.

## 질문과 목표

“인증 로그의 성공 기록과 실제 세션 기록이 일치하는가?” auth.log/secure만 보지 않고 utmp·wtmp·btmp·lastlog의 의미와 한계를 비교합니다. 05장의 실패 집계, 02장의 시간대·사본 관리가 선수지식입니다. 09장의 테스트 원칙을 분석 가설에도 적용합니다.

## 네 가지 아티팩트

| 자료 | 주요 의미 | 읽는 도구 | 주의 |
|---|---|---|---|
| utmp | 현재 로그인/세션 상태 정보 | who, w | 모든 접속 방식이 기록하는 것은 아님 |
| wtmp | 로그인·로그아웃·부팅 등 이력 | last | 전체 명령 이력이 아님 |
| btmp | 실패 로그인 기록 | lastb | 모든 인증 실패와 일대일 대응 아님 |
| lastlog | 계정별 최근 로그인 정보 | lastlog | 모든 과거 세션 목록 아님 |

이들은 단순 텍스트 로그가 아닙니다. 배포판·라이브러리·도구 세대에 따라 저장 방식과 지원 여부가 달라질 수 있습니다. 파일이 없으면 0건이 아니라 존재·로테이션·수집·지원 여부를 확인합니다. lastlog2를 쓰는 시스템은 해당 도구와 원본 형식을 별도로 확인합니다.

## 라이브 조회와 사본 조회

다음은 승인된 Ubuntu VM의 현재 자료 조회 예입니다.

```bash
TZ=Asia/Seoul who
TZ=Asia/Seoul w
TZ=Asia/Seoul last
TZ=Asia/Seoul lastb
TZ=Asia/Seoul lastlog
```

lastb는 보통 추가 읽기 권한이 필요합니다. 권한 오류를 숨기거나 임의 권한 변경으로 우회하지 않습니다. 실제 수집한 wtmp/btmp 사본은 다음처럼 지정합니다. `evidence/`는 해당 형식의 승인된 수집 사본 경로입니다.

```bash
TZ=Asia/Seoul last -F -i -f evidence/wtmp
TZ=Asia/Seoul lastb -F -i -f evidence/btmp
```

-f는 입력 사본, -F는 전체 시간, -i는 숫자 IP 표시입니다. 자신의 last 버전에서 지원 여부를 확인합니다. 결과의 사용자·터미널·출발지·시작/종료·기간을 함께 봅니다. still logged in은 수집된 자료 기준 표시일 수 있으므로 현재 연결 존재와 혼동하지 않습니다. 사본 구조가 맞지 않으면 빈 결과를 정답으로 취급하지 않습니다.

## 합성 실습과 원래 바이너리를 구분하기

제공 login-review.psv는 위 아티팩트에서 확인할 정보를 **교육용으로 요약한 텍스트**입니다. wtmp를 생성하거나 파싱한 자료가 아닙니다. 이 파일에 last -f를 실행하지 않습니다. 필수 실습은 요약 필드의 의미와 교차 판단을 연습하고, 원래 바이너리 도구 실행은 별도 VM 자료가 있을 때만 합니다.

```text
btmp-summary    09:01:10 실패
wtmp-summary    09:02:00 세션 시작
lastlog-summary 09:02:00 최근 로그인
utmp-summary    09:10:00 수집 당시 존재
```

4행을 성공 로그인 4건으로 합산하면 중복 계산입니다. 하나의 흐름을 서로 다른 관점에서 보여줄 수 있습니다. auth.log의 공개키 성공 1건과 같은 계정·주소·시각을 비교하되 공격자 동일성은 확정하지 않습니다.

## sudo·su·계정 활동

sudo 실행 메시지는 위임 작업을, su/PAM 세션 메시지는 계정 전환 관련 흐름을 보여줄 수 있습니다. 특정 명령의 기록은 명령 전체 결과·의도까지 증명하지 않습니다. 신규 계정·UID 변경·관리자 그룹 변경은 계정 파일 기준선·Audit·승인 변경과 비교합니다. 마지막 로그인만으로 계정 생성 시각을 추정하지 않습니다.

### Bash Point — 형식 검증도 테스트

```bash
awk -F '|' 'NR>1 && NF!=5 {bad=1} END {exit bad}' "$COURSE_OUT/malformed.psv"
```

이 검사는 제공 요약 형식의 필드 수만 확인합니다. 실제 날짜·주소·아티팩트 종류의 의미 검증까지 했다는 뜻은 아닙니다. 09장의 정상·빈 입력·오류 테스트를 확장해 형식 변경, 중복 자료, 시간대 누락, 회전 경계도 사례로 만듭니다.

## Red / Blue 관점과 탐지

원격 접근이라는 가설 → 인증·세션 흔적 → 서로 다른 자료의 시각·계정 비교 → 후속 프로세스·서비스 활동 확인 → 접근 정책·MFA·키 관리·보존 개선으로 연결합니다. 기록 부재는 삭제 가능성뿐 아니라 애초 미기록·회전·누락도 원인입니다. 삭제나 우회 방법을 실습하지 않습니다.

## 실습·평가

ch09.sh의 기대값은 아티팩트 4행, 공개키 성공 1행, 09:02 세션 시각, 잘못된 2필드 행 거부입니다. 다음에 답합니다.

1. 성공 건수가 서로 다른 자료에서 다르면 무엇부터 확인하는가?
2. lastlog와 wtmp를 합산하면 왜 안 되는가?
3. 실패 뒤 성공이 침해를 확정하지 못하는 이유는 무엇인가?
4. 원래 바이너리를 검증하지 않은 범위를 보고서에 표시했는가?

사실·불일치·누락·추가 확인을 분리하고 잘못된 입력 테스트를 통과하면 완료입니다.
