# 07-2. dry-run·멱등성·실패 시 보존

자동화는 한 번 성공하는 것뿐 아니라 다시 실행하거나 중간에 실패했을 때의 결과가 분명해야 한다. dry-run은 변경 계획을 표시하고, 멱등성은 같은 요청의 반복이 불필요한 추가 변화를 만들지 않게 한다.

{% hint style="info" %}
### 🧭 학습 목표

- 입력 검증·계획·실행·검증을 나눈다.
- dry-run에서 생성·수정이 없는지 확인한다.
- 재실행 충돌 정책을 문서화한다.
- 임시 결과와 최종 결과를 분리한다.
{% endhint %}

## 학습 전 확인

dry-run에서도 출력 폴더를 만들면 변경 없는 미리보기인가? 기존 결과가 있을 때 덮어쓰기와 새 버전 생성 중 무엇이 필요한가?

## 1. 네 단계의 흐름

```text
입력 형식·대상 확인 → 수행 계획 작성 → 실제 변경 → 결과 재확인
                            │
                            └─ dry-run: 계획 출력 후 종료
```

검증은 dry-run에서도 필요하다. 불가능한 작업을 성공할 것처럼 출력하면 계획을 신뢰할 수 없다. 반면 로그 파일 생성도 변경이므로 dry-run 진단은 stderr로 보낸다.

## 2. 간단한 계획 함수

```bash
plan_report() {
    (( $# == 2 )) || return 2
    local input=$1 output=$2
    [[ -f $input && -r $input ]] || return 1
    [[ ! -e $output && ! -L $output ]] || return 1
    printf 'read=%q\nwrite=%q\n' "$input" "$output"
}
```

이 함수는 결과를 만들지 않는다. 실행 단계는 같은 검증을 다시 확인해야 한다. 계획 후 파일시스템이 바뀔 수 있기 때문이다.

## 3. 충돌 정책 선택

| 정책 | 장점 | 필요한 처리 |
|---|---|---|
| 기존 결과 거부 | 실수로 덮어쓰기 방지 | 충돌 시 0이 아닌 종료 상태 반환 |
| 동일 내용이면 유지 | 재실행에 안정적 | 내용 또는 해시 비교 |
| 버전별 디렉터리 | 실행별 증거 보존 | 보존·정리 규칙 |
| 원자적 교체 | 최신 결과 제공 | 임시 저장·검증·교체 |

교재의 종합 로그 보고서는 기존 결과를 거부한다. 자동 갱신 보고서는 [04-3](../04-file-io/04-3-streams-atomic-output.md)의 원자적 교체를 선택할 수 있다. 정책은 도구마다 명시한다.

## 4. 중단 시 상태

작성 중인 결과를 최종 파일 이름으로 저장하면 다른 프로그램이 미완성 보고서를 읽을 수 있다. 임시 파일에 결과를 쓴 뒤, 검증에 성공했을 때만 최종 이름으로 저장한다. 실패하면 원본과 기존 결과가 유지되어야 한다.

trap은 자기가 만든 정확한 임시 경로만 정리한다. 변수가 비었을 때 넓은 경로로 바뀌는 정리 구문은 만들지 않는다. 큰 정리 작업은 교재 실습 범위를 벗어나므로 소규모 명시적 파일을 대상으로 한다.

## 5. 로그와 비밀정보

로그에는 실행 ID, 시각, 단계, 상태를 남긴다. 비밀번호나 환경 전체는 남기지 않는다. set -x는 확장된 인수를 출력하므로 실제 자격증명을 사용하는 구간에는 적합하지 않다.

## 🧪 직접 해보기

1. 입력 하나와 존재하지 않는 결과 경로로 plan_report를 실행한다.
2. 실행 전후 파일 목록을 비교해 생성이 없는지 확인한다.
3. 기존 결과가 있을 때 상태 1로 거부하는지 확인한다.
4. 종합 프로젝트에서 dry-run, 정상 실행, 재실행의 결과를 비교한다.

### 해설

멱등성은 “무조건 성공으로 종료”가 아니다. 재실행을 명확히 거부하는 것도 충돌 정책이며, 동일 상태로 수렴하는 멱등 동작과 용어를 구분한다.

## ✅ 완료 기준

- [ ] dry-run의 변경 없음이 검증된다.
- [ ] 재실행 시 기존 결과가 보존된다.
- [ ] 실패한 부분 결과가 최종 이름으로 남지 않는다.
