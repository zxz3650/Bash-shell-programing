# 06-4. 네트워크 상태와 프로세스 연결 해석

## 개요와 목표

로컬 인터페이스·라우트·이웃·수신 포트·연결을 구분합니다. 이 절은 외부 호스트를 탐색하거나 연결을 시도하지 않습니다. 네트워크 정보가 공격자에게 어떤 의미인지 개념적으로 이해하고, 분석가는 정상 서비스와 비정상 통신의 근거를 구분합니다.

## 주소·경로·이웃은 다른 정보

Ubuntu VM의 읽기 전용 조회:

```bash
ip addr
ip route
ip neigh
cat /etc/resolv.conf
```

| 정보 | 무엇을 확인하는가 | 무엇을 증명하지 못하는가 |
|---|---|---|
| addr | 인터페이스·주소·prefix | 외부에서 접근 가능함 |
| route | 목적지별 경로·gateway·장치 | 실제 연결 성공 |
| neigh | ARP/ND 이웃 캐시·상태 | 전체 내부 자산 목록 |
| resolv.conf | 이름 해석 설정·stub | 실제 질의 이력·최종 upstream 전체 |

교육용 예 `192.0.2.20/24`, `default via 192.0.2.1`은 인터페이스 주소와 기본 경로를 뜻합니다. 공격자는 도달 가능한 환경을 이해하려 할 수 있지만, 이 값만으로 내부 이동·터널 사용 가능성을 확정할 수 없습니다. 방어자는 예상 네트워크와 차이가 있는지 기준선에 비교합니다.

## 수신과 연결

```bash
ss -tulpn
ss -antp
lsof -nP -iTCP
```

ss의 첫 예는 TCP/UDP 수신 소켓, 두 번째는 TCP 전체 상태를 숫자로 확인합니다. -p 정보는 권한이나 프로세스 수명에 따라 없을 수 있습니다. lsof는 열린 파일과 소켓을 프로세스에 연결하며 시스템에 설치되지 않았을 수 있습니다. 표시가 비었다고 프로세스가 없는 연결이라고 단정하지 않습니다.

```text
LISTEN 0.0.0.0:22       peer=0.0.0.0:*        pid=200
ESTAB  192.0.2.20:41000 peer=203.0.113.7:443 pid=520
```

0.0.0.0은 모든 IPv4 로컬 주소의 바인딩 의미이며 인터넷 공개 여부는 라우팅·방화벽·NAT가 결정합니다. 443은 포트 번호일 뿐 TLS나 정상 웹 연결을 보증하지 않습니다. ESTAB은 수집 시 TCP 상태이지 전체 세션 내용이나 실행 의도가 아닙니다.

## 조사 흐름

예상 밖 연결 → PID/실행 경로/사용자 → 서비스·시작 시각 → 승인된 목적지·배포 이력 → DNS·프록시·방화벽·EDR 기록 순으로 검토합니다. C2·reverse shell·내부 스캔·lateral movement는 행위 가설이며 소켓 한 행으로 확정하지 않습니다. 주기성·다수 목적지·프로세스 계보·세션 근거를 결합합니다.

## Bash Point — 필드 조인의 한계

ch06.sh는 두 합성 스냅샷을 PID로 조인합니다. 같은 호스트·같은 기간이라는 전제가 있어야 합니다. 다른 부팅의 동일 PID를 연결하면 잘못된 결과가 됩니다. 운영 분석에서는 호스트·부팅 ID·시작 시각·수집 시간창을 함께 보존합니다.

## 실습과 질문

linked.psv에서 PID 520의 목적지·실행 경로를 찾아 추가 확인 항목 세 가지를 작성합니다. 정상 모니터링 에이전트라는 반례도 제시합니다. 예상 결과는 `verdict=needs_service_and_destination_review`입니다. 이는 자동 악성 판정이 아니라 다음 조사 단계입니다.

## 실패 사례·완료 기준

- neigh를 전체 자산 목록이라고 부르지 않습니다.
- 임의 목적지에 접속해 반응을 확인하지 않습니다.
- 포트 번호를 애플리케이션 인증으로 사용하지 않습니다.
- DNS 역조회로 불필요한 외부 질의가 생기지 않도록 숫자 표시를 사용합니다.
- 부족한 권한과 0건을 구분합니다.

각 연결을 프로세스·시각·정상 기준선에 연결하고 미확인 부분을 표시하면 완료입니다.

## Red Team ↔ Blue Team 사례 분석

### 사례: 수신 포트와 외부 연결의 의미

**Red Team 질문:** 로컬 주소·라우트·수신 상태가 어느 접근 경계를 보여주는가? 내부 이동이나 피벗 가능성에는 실제 접근 통제 등 추가 조건이 필요합니다. 이 실습은 로컬 자료의 의미를 검토하며 원격 탐색·터널 구성은 하지 않습니다.

| 연결 단계 | 분석 내용 |
|---|---|
| Goal / Boundary | 서비스 접근·통신 경계 이해. 라우팅·방화벽·NAT·서비스 인증은 별도 조건 |
| Command / Observation | ip·ss·lsof와 프로세스 사본을 연결. PID 520의 peer는 203.0.113.7:443 |
| System Change / Artifact | 소켓 생성·연결 상태. 소켓 한 행은 전송 내용·명령 실행을 담지 않음 |
| Log prerequisite | DNS·프록시·방화벽 flow·EDR 등의 실제 수집 여부. ss를 실행했다고 과거 통신 로그가 생기지 않음 |
| Blue Team Investigation | 프로세스 신원·승인 목적지·통신 기간·전송량·관련 서비스 변경 검토 |
| Detection | 예상 밖 프로세스와 목적지의 조합, 시간 패턴, 여러 기록의 일치로 조사 후보 구성 |
| Mitigation | 승인된 통신 범위·서비스 노출·원격 관리 정책 검토. 차단은 증거 보존과 업무 영향 고려 |

**반례와 해설:** 정상 모니터링 프로그램도 주기적으로 443에 연결합니다. 반대로 443이라고 내용이 TLS이거나 안전하다고 보장되지 않습니다. C2·Reverse Shell은 조사 가설이지 이 사본의 결론이 아닙니다. 목적지 IP를 확인하려고 수업에서 실제로 접속하지 않습니다.

**제출 과제:** LISTEN 한 행과 ESTAB 한 행의 차이를 설명하고 각각 가능한 정상 업무를 적습니다. 경보에 사용할 필드 세 개와 현재 없는 필드 두 개를 구분합니다. 서로 다른 호스트의 같은 PID를 조인하지 않는 기준을 적으면 통과입니다.
