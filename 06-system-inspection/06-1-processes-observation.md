# 06-1. 프로세스와 로컬 시스템 상태 읽기

프로세스는 실행 중인 프로그램의 인스턴스다. PID 하나만으로 정체를 설명할 수 없으므로 부모, 사용자, 시작 시각, 명령을 함께 관찰한다. 여기서는 자기 컴퓨터의 상태를 읽으며 외부 호스트에 연결하지 않는다.

{% hint style="info" %}
### 🧭 학습 목표

- PID·PPID·사용자·시작 시각을 연결한다.
- 셸 builtin 상태와 시스템 명령 결과를 구분한다.
- Linux 전용 명령과 공통 명령을 구분한다.
- 스냅샷의 시간적 한계를 설명한다.
{% endhint %}

## 0. 학습 전 확인

PID가 같으면 항상 같은 프로세스인가? `$SHELL`이 현재 프로세스 이름을 보장하는가?

## 1. 현재 프로세스 계보

```bash
printf 'shell pid=%s parent=%s\n' "$$" "$PPID"
ps -p "$$" -o pid,ppid,user,comm
uname -s
```

출력 숫자는 환경마다 다르다. PID와 PPID가 ps의 필드와 어떻게 연결되는지 확인한다. PID는 재사용될 수 있으므로 장시간 수집 결과는 시각과 함께 기록한다.

```bash
TZ=Asia/Seoul date '+%Y-%m-%dT%H:%M:%S%z'
ps -eo pid,ppid,user,comm | sed -n '1,16p'
```

미리보기는 전체 프로세스 목록이 아니다. 조사를 위한 완전한 목록과 화면에 보여 줄 제한된 목록을 구분한다. args에는 자격증명이 포함될 수 있으므로 필요할 때만 수집한다.

## 2. Linux의 /proc

Linux에서만 실행한다.

```bash
pid=$$
readlink "/proc/$pid/exe"
tr '\0' ' ' < "/proc/$pid/cmdline"
printf '\n'
```

cmdline은 NUL로 인수를 구분한다. 화면에 보이도록 공백으로 바꾸면 원래 인수 경계 정보가 손실된다. 사람이 읽는 미리보기와 원본 데이터 보존은 다르다. 접근 실패는 권한 제한이나 프로세스 종료 때문일 수 있다.

## 3. 상태 수집 명령의 범위

| 질문 | Linux | macOS 대안 |
|---|---|---|
| OS 종류 | uname -s | uname -s |
| 디스크 사용 | df -h | df -h |
| 프로세스 | ps | ps, 옵션 차이 확인 |
| 로컬 수신 소켓 | ss -lnt | lsof -nP -iTCP -sTCP:LISTEN |
| 인터페이스 | ip address show | ifconfig |

수신 포트가 있다는 사실만으로 외부 노출이나 침해를 확정할 수 없다. 바인딩 주소, 방화벽, 실제 통신 기록을 함께 해석해야 한다. 이 교안에서는 로컬 목록을 읽는 수준으로 한정한다.

## 4. 스냅샷의 일관성

프로세스 목록과 소켓 목록은 서로 다른 시점에 수집된다. 그 사이 프로세스가 종료될 수 있다. 수집 시작·종료 시각, 성공 여부, 도구 버전을 기록하면 차이를 설명할 수 있다.

한 명령이 없다고 전체 수집을 정상 성공으로 표시하지 않는다. 필수 항목은 실패, 선택 항목은 skipped로 구분한다.

## 🧪 직접 해보기

1. 현재 Bash와 부모 PID를 기록한다.
2. 2초 간격으로 목록을 두 번 수집해 차이를 설명한다.
3. Linux 전용 명령을 macOS에서 실행할 때 실패 메시지를 기록한다.

### 해설

기대하는 것은 고정 PID가 아니라 필드가 존재하고 수집 시점이 기록되는 것이다. 시스템 결과를 정적 문자열과 완전히 일치시키는 테스트는 적합하지 않다.
