# 첫 조사 기록 실습

01장의 보안 질문·명령·출력 해석을 연결하는 교육용 자료입니다. 모든 명령은 자기 환경의 기본 정보 또는 제공된 합성 자료만 사용합니다. 네트워크 조사, 권한 변경, 비밀정보 검색, 실제 공격은 수행하지 않습니다.

## 입력 자료와 출처

`fixtures/case.txt`는 직접 작성한 고정 교육용 자료입니다. 실제 사건 로그나 계정 목록이 아닙니다. `6.8.0-lab`도 해석 연습용 표식이며 취약한 커널을 지정하지 않습니다. 시각은 KST(`UTC+09:00`)입니다.

## 명령 실행

저장소 루트에서 실행합니다.

```bash
cat examples/first-observation/fixtures/case.txt
bash examples/first-observation/observe-context.sh
bash tests/test-first-observation.sh
```

관찰 도구는 Bash 3.2 이상과 `date`, `hostname`, `uname`, `id`, `ps`, Asia/Seoul 시간대 데이터가 필요합니다. Ubuntu VM이 기준입니다. 공통 명령은 macOS에서도 검증할 수 있지만 그 결과는 Linux 서버 증거가 아닙니다. 컨테이너에서는 해당 컨테이너 관찰이라고 기록합니다.

## 출력과 종료 상태

- 인수 없음: 자기 호스트·커널·실효 UID/GID·Bash 버전·자기 프로세스·KST 관찰 시각을 stdout에 표시합니다.
- 성공은 0, 수집 실패는 1, 인수가 있으면 사용 오류 2입니다.
- 명령 실행 실패나 필수 출력 누락이면 최종 보고서를 stdout에 내보내지 않고 stderr에 알립니다.
- 출력은 사람을 위한 관찰 형식입니다. 임의 필드 값의 탭·개행을 처리하는 범용 데이터 교환 형식은 아닙니다.
- 도구는 파일을 쓰지 않습니다. 저장은 교안의 새 실습 폴더에서 수행합니다. 출력 쓰기 자체의 실패도 호출자가 종료 상태로 확인해야 합니다.
- 명령별 관찰 시점은 다릅니다. complete는 정해진 수집 명령의 완료이며 전체 시스템의 일관된 스냅샷이나 침해 없음의 판정이 아닙니다.

## 고정 자료 분석의 기대 답변

| 질문 | 기대 답변 |
|---|---|
| 자료의 출처는? | source_type=synthetic인 교육용 자료 |
| 시각의 시간대는? | KST, UTC+09:00 |
| 로그인 셸과 관찰한 셸이 같은가? | zsh와 Bash로 다르며 이 자체는 오류가 아님 |
| sudo 그룹에서 root 명령 실행을 입증하는가? | 아니오. 정책·실제 실행 증거가 더 필요함 |
| Audit 기록이 없다고 판단 가능한가? | 아니오. coverage가 unknown인 것만 확인됨 |
| 이 자료로 침해를 확정 가능한가? | 아니오. 승인 작업 등 맥락과 추가 증거 필요 |

## 테스트 범위

테스트는 자기 환경의 정상 출력 구조, KST 오프셋, 사용 오류, 수집 명령 실패, 잘못된 시간대 출력, 빈 필수 출력, 인용과 스트림 분리를 검증합니다. 명령 실패는 임시 폴더 안의 테스트 대역으로 재현하며 시스템 파일이나 실제 명령을 바꾸지 않습니다.

테스트 대역을 실행해야 하므로 임시 작업 위치에 실행을 금지하는 noexec 설정이 있으면 검증을 중단하고 원인을 표시합니다. 보안 설정을 해제하지 말고 수업에서 승인된 실행 가능한 작업 위치를 TMPDIR로 지정합니다. 운영 서버가 아닌 준비된 실습 환경에서 검사합니다.

이 검사는 실제 사건의 진실성, 운영체제 신뢰성, 모든 파일시스템 경계에 대한 보안 보장을 제공하지 않습니다. 링크와 구문 검사는 기존 `scripts/validate_course.py`를 함께 사용합니다.
