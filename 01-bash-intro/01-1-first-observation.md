# 01-1. 첫 조사에서 확인할 정보

## 개요

서버 점검 요청을 받았다고 가정합니다. 아직 침해 여부는 모릅니다. 첫 작업은 공격 흔적을 단정하는 것이 아니라 **지금 보고 있는 결과가 어떤 환경의 결과인지 확인하는 것**입니다. 다른 VM의 출력이나 컨테이너 안의 계정을 호스트 전체의 정보로 오해하면 이후 분석도 틀어집니다.

## 학습 목표

- 호스트·커널·사용자·프로세스 정보가 각각 답하는 질문을 설명합니다.
- 출력의 숫자와 이름을 구분하고 조사 범위를 기록합니다.
- 간단한 명령 치환과 인용으로 관찰 결과를 표시합니다.
- 단일 출력으로 권한 상승 가능성이나 침해를 확정하지 않습니다.

## 준비와 조사 범위

Ubuntu VM의 일반 사용자 터미널 또는 자기 JupyterLab의 `%%bash` 셀을 사용합니다. 설치는 [02장](../02-bash-setup.md), 용어는 [01장](../01-bash-intro.md)을 참고합니다. 아래 명령은 로컬 기본 정보와 자기 셸을 관찰합니다. 관리자 권한, 외부 접속, 전체 사용자 환경 변수 출력은 필요하지 않습니다.

컨테이너·WSL·Colab에서는 그 실행 환경에서 보이는 정보를 기록합니다. 물리 서버 전체의 상태를 얻었다고 적지 않습니다. 명령의 관찰 범위를 보고서의 한 필드로 남깁니다.

## 1. 보안 질문에서 명령 선택하기

| 질문 | 필요한 정보 | 기본 명령 | 출력에서 볼 부분 |
|---|---|---|---|
| 어떤 환경인가? | 호스트 이름 | `hostname` | 조사 대상 표식과 일치하는가 |
| 어떤 커널인가? | OS 종류·커널 릴리스 | `uname -s`, `uname -r` | 도구·로그 분석 환경과 호환되는가 |
| 어떤 배포판인가? | OS 배포판 설명 | `cat /etc/os-release` | NAME·VERSION_ID 등, 파일 존재 여부 |
| 누구의 권한인가? | UID·GID·그룹 | `id` | 실효 권한과 그룹 목록 |
| 어떤 셸이 실행 중인가? | Bash 버전·PID·PPID | `printf`, `ps` | 실제 프로세스와 부모 관계 |
| 언제 관찰했는가? | 시각·시간대 | `date` | KST 표시와 숫자 오프셋 |

`hostname`은 운영자가 바꿀 수 있는 이름입니다. 고유한 장비 식별이나 증거의 진위를 보장하지 않습니다. `uname -r`의 문자열만으로 패치 적용 여부를 확정하지 않습니다. 배포판의 패키지와 보안 공지 확인은 이후 구성 진단에서 다룹니다.

## 2. 호스트와 커널 관찰

```bash
hostname
uname -s
uname -r
```

교육용 출력 예:

```text
lab-ubuntu
Linux
6.8.0-lab
```

이 값은 실제 취약한 버전을 가리키는 자료가 아니라 해석 연습용입니다. 학생의 호스트명과 커널 버전은 달라도 됩니다.

Linux 배포판 정보는 다음처럼 읽습니다. 파일이 없는 환경에서는 오류를 그대로 기록합니다.

```bash
cat /etc/os-release
```

예시의 `NAME="Ubuntu"`, `VERSION_ID="24.04"`는 배포판 설명입니다. 커널 릴리스와 같은 항목이 아닙니다. 파일을 읽기 위해 `source /etc/os-release`를 사용할 필요는 없습니다. `source`는 단순 읽기가 아니라 코드 실행입니다.

> **Bash Point — Command Substitution와 Quoting**

```bash
kernel=$(uname -r)
printf 'kernel=%s\n' "$kernel"
```

`$(...)`는 명령의 stdout을 받아 변수에 담습니다. 끝의 개행은 제거됩니다. `"$kernel"`은 값을 한 인수로 전달합니다. 명령 치환 자체가 성공 여부를 검증하지는 않으므로 완성 스크립트에서는 실패 상태도 처리합니다.

## 3. 사용자와 그룹 해석

```bash
id
id -u
id -g
```

교육용 출력 예:

```text
uid=1000(analyst) gid=1000(analyst) groups=1000(analyst),27(sudo)
1000
1000
```

| 관찰 | 말할 수 있는 것 | 아직 말할 수 없는 것 |
|---|---|---|
| UID 1000 | 현재 출력의 사용자 ID가 1000 | 모든 Linux에서 1000이 같은 계정 유형이라는 결론 |
| GID 1000 | 출력에 표시된 기본 그룹 ID | 모든 보조 그룹의 권한 |
| sudo 그룹 포함 | 그룹 소속을 추가 점검할 이유가 있음 | 모든 명령을 root로 실행할 수 있다는 결론 |
| UID 0 | 관찰된 문맥에서 강한 권한의 계정임 | 모든 namespace·보안 정책을 초월하는 권한 |

`id`는 실제 ID와 실효 ID가 다르면 추가 정보를 표시할 수 있습니다. `id -u`는 기본적으로 실효 UID를 출력합니다. 계정 이름과 숫자 ID의 대응도 환경마다 다르므로 숫자를 함께 보존합니다. 이 장에서는 sudo 실행이나 권한 변경 실습을 하지 않습니다.

## 4. 로그인 셸과 현재 셸 구분

```bash
printf 'configured_login_shell=%s\n' "${SHELL-unset}"
printf 'bash_version=%s\n' "$BASH_VERSION"
printf 'shell_pid=%s parent_pid=%s\n' "$$" "$PPID"
ps -p "$$" -o pid,ppid,comm
```

교육용 출력 예:

```text
configured_login_shell=/bin/zsh
bash_version=5.2.21(1)-release
shell_pid=4200 parent_pid=4100
  PID  PPID COMMAND
 4200  4100 bash
```

로그인 셸 설정이 zsh여도 현재 Bash를 실행할 수 있습니다. `$SHELL` 하나만 보고 실행 인터프리터를 판단하지 않습니다. 위 예제의 `$$`는 최상위 Bash 문맥을 전제로 합니다. 괄호 서브셸에서도 `$$`가 부모 셸 값을 유지하는 경우가 있으며, Bash 4 이상의 `BASHPID`와 구별해야 합니다.

노트북에서는 Python 커널이 Bash 자식 프로세스를 시작합니다. 다음 `%%bash` 셀은 새로운 Bash이므로 PID·변수·현재 디렉터리가 계속 유지된다고 가정하지 않습니다.

## 5. KST로 관찰 시각 표시

```bash
TZ=Asia/Seoul date '+%Y-%m-%dT%H:%M:%S%z'
```

교육용 출력 예: `2026-09-10T09:00:00+0900`. `+0900`은 `UTC+09:00`을 뜻합니다. 이 명령은 한 번의 날짜 표시 환경을 바꾸며 시스템 시계를 설정하지 않습니다. 시간대 데이터가 없는 최소 환경에서는 출력 오프셋을 확인해야 합니다.

원본 로그가 `2026-09-10T00:00:00Z`라면 그 값을 보존하고 KST 표시를 별도 열에 둡니다. 문자열 끝의 `Z`를 `+09:00`으로 바꾸는 것은 시간 변환이 아닙니다. 실제 시각 계산과 원본 보존은 다음 장에서 확장합니다.

## Red Team / Blue Team 관점

공격자도 OS·사용자·실행 환경을 이해하려 할 수 있습니다. 분석가는 같은 정보를 조사 범위를 정하고 출력의 의미를 해석하는 데 사용합니다. 이 공통점은 `uname`이나 `id`가 악성 명령이라는 뜻이 아닙니다. 실행 주체·승인된 작업·시각·주변 행위를 함께 보아야 합니다.

## 실패 사례와 수정

| 오해 | 왜 실패하는가 | 수정 방향 |
|---|---|---|
| `$SHELL`이 실제 실행 셸이다 | 설정값과 프로세스가 다를 수 있음 | Bash 버전·PID·프로세스 출력 교차 확인 |
| sudo 그룹이면 무조건 관리자 명령 실행 가능 | 그룹 소속과 위임 정책은 다름 | 정책 검토가 필요하다고 기록 |
| OS 문자열이면 패치 상태를 안다 | 패키지·백포트·배포판 정보가 빠짐 | 추가 자료와 판단 한계를 명시 |
| 명령이 읽기 전용이면 시스템 영향이 없다 | 프로세스 생성·감사 기록·일부 접근 시각 변화 가능 | 라이브 관찰이라고 표시 |

## 실습과 분석 질문

1. 각 명령을 실행하기 전에 예상 출력의 종류를 적습니다.
2. 결과에서 호스트·UID·셸 PID·시간대를 표시합니다.
3. 고정 정답이 될 수 없는 값 세 가지를 고릅니다.
4. `$SHELL`과 현재 Bash가 다를 때 오류인지 설명합니다.
5. “이 계정은 권한 상승이 가능하다”라는 결론을 지금 내릴 수 없는 이유를 적습니다.
